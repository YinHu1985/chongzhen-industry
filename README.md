# 崇祯工业

一款回合制网页小游戏原型：在京师决战前，把工业试验变成持续供军的生产体系，把新军练成能够作战的部队。为团队指定持续科研目标后，每季统一支付经费并推进准备；项目何时验收由玩家决定，有准备度即可尝试，继续研究则能提高成功率。

当前版本包含 51 项可研究科技、1 项终局胜利成果和 19 组建筑等级／专业扩建，采用工场全景与浮窗操作。在原有百工街巷、山麓炉场、水轮军器厂和演武营城的画面中，按九类建筑分别显现对应楼群，全部落成后仍是原有的完整工业苑全景。研发按建筑大类与等级分组；部队在倭寇、白莲教、闯王军与清军四条战线上逐季交战，工业能力持续补充实际损失，最终按敌军数量与可持续作战状况结算。

默认每回合一季、共 24 回合，从崇祯十一年夏开始，到崇祯十七年春结束。另有 40、64 回合选项，用于比较时间压力。战线采用游戏化的历史背景，倭寇自开局出现，白莲教、闯王军和清军分别在全程的四分之一、二分之一和四分之三处出现；最终截止回合保持固定。

## 本地启动

需要 Node.js 22 或更高版本，建议 Node.js 24。项目没有第三方运行或构建依赖，无须安装依赖。

```sh
npm run dev
```

在浏览器打开 <http://127.0.0.1:4173/>。开发服务器只监听本机。修改源文件后刷新浏览器即可看到变化。

更换端口：

```sh
npm run dev -- --port 4174
```

也可设置 `PORT` 环境变量。游戏使用 JavaScript modules，请通过本地 HTTP 服务打开，不要直接双击 `index.html`。

## 试玩

- 打开页面先进入标题界面，可选择「继续游戏」「新游戏」或「读取存档」。新游戏可选择 24、40、64 季及 0.10—10.00 倍敌军战斗力（默认 1.00 倍）；仅浏览标题页不会生成或覆盖存档。游戏右上角菜单按钮可返回标题。系数可拖动滑条或精确输入，步长 0.01；1.00 就是基准战力、10.00 就是十倍，开局后固定。
- 「读取存档」支持此前导出的 JSON 卷宗（不超过 2 MB）。读取后先显示日期、季度和银两，确认后才替换当前进度；校验失败或取消读取不会改动原来的卷宗。
- 背景音乐为原创循环曲《甲申未至》，约 71 秒，无外部采样。首次点击后开始播放，标题页可以调整音量，标题页与游戏右上角都可开关音乐；偏好会保存在本机，页面隐藏时暂停。播放器独立于界面刷新，不因研究、换季或切换面板而重新播放。
- 可操作按钮使用统一的轻短点击音，支持鼠标和键盘点击；禁用按钮与换季过场不发声。点击音与背景音乐独立，标题页可单独开关或调音量，偏好保存在本机。
- 从全景打开研发、营建、练军和目标浮窗；浮窗可收起，回到场景查看建设成果。
- 天工密录按基础工坊、炼铁炉场、机械工场、火器工场、演武场五类建筑分卷。每个等级或专业扩建是一组，科技从上向下排列并画组内依赖线；各组横向并列，空间不足时整组换行，组内关系保持不变。左侧团队栏和底部三格详情保留。建筑解锁格子可在多个相关组内重复出现，均指向同一项建设。
- 先选左侧团队，再选科技，点击「设为目标」即可安排持续研究，无须下拉选择团队。所选团队的信息、研究进度与目标／验收按钮固定留在底部左栏；点击在研科技会自动选中负责团队，点击有任务的团队也会自动显示对应科技。没有研究任务时，两格科技详情显示空位。
- 技术背景栏直接展示技术概述、原理和历史沿革，不需要展开；玩法作用与前置条件在相邻的科技信息栏展示。
- 52 项科技成果各有独立配图；研究卡片以灰度图表示前置未满足，完成状态使用旧金边框与完成标记，选中状态另有边框强调，同时保留文字状态。工艺背景栏使用同一张淡化插画，保证背景文字可读。
- 点击建筑格子可查看完整营建条件与本级研究；实线表示必需条件，虚线表示任选条件，跨组条件集中显示在建筑入口。科研目标跨季保留，季末统一扣费并推进准备，持续至准备度达到 100%、验收完成或取消。浏览其他项目不会改派任务；可点击「更换目标」或「取消研究」，已有准备度保留。满 100% 后暂停科研收费，可择机验收或安排新目标。
- 原有工业里程碑已由建筑等级及组内前置取代。升级保留低等级科技，不要求点满上一组；不同工艺路线可以并行。机械工场Ⅱ同时要求卧式镗床、金属刨床、材料与成品检验、工匠学堂。镗床与刨床分别提供产能，彼此不会覆盖。
- 开局仅有钦天监（数学特长）与神机营（军事特长）。研究时选择适合的团队，其专长影响每季推进的概率。持续科研会预留团队，必须先取消目标才能营建或操演；已在本季营建或操演的团队，要到下季才能安排研究。
- 六类团队模板头像按最高能力自动适配；能力并列时按专长栏顺序固定选择。团队列表、研究详情、在署与候选卡片，以及营建、操演中的负责团队均展示对应头像。
- 可付费刷新候选团队、雇用或解雇团队，编制为 1 至 8 支；候选人被雇用后从候选名单移入现有团队。初始及刷新名单均有三位候选，每个名额有 30% 概率抽到尚未在署的特殊人物：徐光启（洋务、管理）、汤若望（数学、洋务）、孙元化（机械、军事）、宋应星（机械、冶金）、李之藻（机械、管理）、方以智（数学、冶金）。人物两项特长均为 92，其余能力为 40；同批名单不重复，六人全部入署后只生成普通团队。普通团队能力仍随机生成，名称由地名与特长组成，不带数字后缀，也不与当前在署或同批候选重名。
- 每季开始前（含开局）有 20% 概率触发一次随机事件，再从符合条件的事件中按权重抽取一种。当前三种等权事件为「锦衣卫发现隐世村庄」（随机一项未满科技准备度 +40 个百分点、威望 +1，不给银两）、「锦衣卫查抄贪官」（银两 +2,000）、「地方进呈祥瑞」（威望 +2）。未解锁科技也可获得准备度，最多达到 100%，仍须满足前置并验收；全部普通科技准备已满时，村庄事件暂不进入抽取池。
- 事件先一次性结算并保存，再显示奏报；「阅毕」只关闭窗口，读档与反复显示不会重复发奖。新季事件在旧季科研、财政、战事和终局判定之后触发，银两计入交接季报及财政明细，威望增加从新季拨款开始体现。已经结束的战局不再触发事件。
- 事件框架位于 `src/events.js`：`EVENT_TRIGGERS` 配置各触发时机及总概率，`EVENTS` 定义事件所属时机、权重、文案与效果列表。当前共用 `research_progress`、`money`、`reputation` 三种效果处理器，并由效果判断能否触发；增加同类事件只需添加配置，增加时机可复用 `triggerRandomEvent`。事件随机数、已检查时机、历史及未阅事件均独立保存，不消耗科研与招募的随机数序列。
- 先营建「基础工坊」，再推进勘察、量具、动力等基础研究；工艺成果解锁后续建筑或等级，逐步打开后续研发。
- 基础工坊有 2 级、炼铁炉场 3 级、机械工场 3 级、火器工场 5 级、演武场 2 级，另有金属弹药、锻钢、青铜炮和线膛炮四项独立扩建。可直接选择更高目标等级，一次合并营建所有缺级、支付各缺级费用并占用一支空闲团队；明确的技术及跨建筑条件仍须满足，不要求研究完中间等级的科技。例如炉场Ⅰ可合并升至Ⅲ，支付Ⅱ、Ⅲ合计 106,000 两，无须先研究熟铁或坩埚钢。四处原有建筑Ⅰ级费用不变。城镇全景沿用原有画面；九类建筑各有固定楼群与同源取景，首次营建显现该区域，升级不改变外观。
- 不同工艺直接体现为科技树中的独立项目，例如土法块炼铁、水力木炭高炉与焦炭高炉。各项目有自己的研究工作量、前置和供军能力，不再额外切换「土法」或「正规工艺」。
- 科研目标与项目验收是两个决定。安排或更换目标不立即扣钱、不立即增加准备度；季末才统一结算。只要准备度大于 0、前置已满足且有验收费用，就可随时独立验收，无须团队，也不限每季次数；验收失败后只要仍有准备度和资金，可以同季重试。遇到可补救的问题时，每次险情可追加资金抢险一次。
- 验收前可选择是否邀请群臣观礼。观礼使成功的威望收益与最终失败的威望损失都翻倍，试验费用、成功率与技术进度损失不变；抢险沿用本次验收的观礼安排，只在最终结果确定时结算威望。
- 科技完成即生效，武器完成即计入军备，不追加换装或列装回合。不同兵器、弹药、产线与训练共同决定实际战力。
- 可选择冷兵器、胸甲骑兵、米尼步枪或后装步枪等军制重点。切换调整作战方案、装备效能和补员速度，已有科技、建筑与训练成果保留，研发目录不会隐藏其他路线。
- 倭寇自开局出现，以较低兵力供早期练兵；白莲教、闯王军（李自成）、清军分别在全程的四分之一、二分之一和四分之三处出现。尚未出现的战线不展示敌军卡片，也不能提前派驻。
- 在「救亡方略」设置各线驻军目标与敌方每季参战上限。调动从预备兵拨付，撤回的部队进入预备兵；只要目标不变，部队便会每季自动剿灭并补员。
- 战斗只按当季实际投入兵力结算。例如敌军共 10 万、参战上限 2 万，则最多按 2 万敌军作战；歼敌数量不能超过其参战兵力。对方剩余大军仍影响后续增长与崩溃风险。
- 我军实际损失会扣除兵力，工业能力每季产生补员。四线共享同一预备兵池与当季补充，先按当季战损补回损失，再把余兵按各线尚缺的驻军目标分配，避免扩编挤占战损补员。持续作战判定也先用当季工业产出覆盖战损；长期损失超过工业补充时，即使有初始预备兵，部队仍会逐渐耗尽。
- 敌军每季获得基础补充，并随规模增长。倭寇兵力低、补充少，适合早期练兵；白莲教兵力与补充较多，形成下一阶段的压力；闯王军单兵较弱，但兵力、参战规模与补充带来的整体压力高于白莲教；清军兵力与战力俱强。缺少成套炮兵或骑兵时，敌军还会获得相应优势。
- 敌军数量设有保底和封顶，不会被永久清零。任何战线超过崩溃线，立即结束本局；各线卡片公开当前数量、平定线、崩溃线、预计战损、补充与上季战报。
- 开局内库可用银 3.5 万两。每季拨款为保底 6,000 两，加上每点朝廷威望对应的 200 两；科技首次完成增加威望，科技和建筑不另外产生经营收入。
- 财政页面列出预计收入、科研队列开销、净收入与结算后余额，并保留已发生的收支明细。资金必须足以支付当季科研费用才能结束本季，不能用尚未到账的下季拨款垫支；可取消研究降低开销。
- 「劝输助饷」每次消耗 5 点威望、立即获得 10,000 两；同时每季威望拨款减少 1,000 两，威望不足 5 时不可使用。
- 结束本季会统一处理科研经费与进度、财政拨款和四线战斗，产生可回看的季度结算报告；最终回合也结算当季收支。
- 朝廷威望降到负数时，立即触发「群臣进献红丸」结局，本局结束，不再拨款或推进季度；威望恰为零仍可继续。
- 最后一季仍可研究、训练和调兵；只有结束该季，完成战斗和补员后才判定终局。四线敌军均不超过平定线，判定胜利；否则，若其余未平定战线均能用当季工业补充覆盖自身损失，且歼敌超过敌方补充，判定僵持（已平定的战线直接视为稳固）；其余为失败。
- 多线同时失败时，按闯王军、清军、白莲教、倭寇的顺序决定结局：闯王军失守为「煤山上吊」，清军失守为「清军入关」，白莲教失守为凤阳遭焚、群臣献上红丸，倭寇失守为沿海失守、群臣献上红丸。

浏览器会自动保存本地进度。存档属于当前浏览器与网址；更换端口、浏览器或部署到新网址后不会自动共享。清理站点数据会删除当地存档。原型不依赖账号、后端或云存储。

本轮采用 v10 存档，保存各建筑已建成的最高等级，使用独立的本地存档槽，不兼容旧版卷宗。敌军战斗力直接保存为两位小数系数。右上角可导出本局 JSON 文件留存；载入时会校验团队、项目、回合、待处理决策和胜负状态。建筑解锁条件与兵种效能由现有成果重新计算，实际兵力、部署目标、科研队列、财政明细、季度结算报告及事件历史会随卷宗保存。

## 史实与游戏依赖

技术背景文字仅介绍技术原理与历史沿革，并提供可查阅的来源。科技作用、依赖关系和准备进度另由界面展示；科技树中的前置关系是玩法设计，不等同于真实历史的发展次序。

界面采用暗朱漆、旧金、乌木与暖灰纸的配色，取材于明代宫廷语境下的红墙黄瓦和剔红器物，参考[故宫《硃黄显尊贵》](https://www.dpm.org.cn/historical/talk/204840.html)与[国家博物馆藏明代剔红盒](https://www.chnmuseum.cn/zp/zpml/csp/201812/t20181218_25430.shtml)。这是一套服务于游戏气氛的宫廷主题，不代表明代所有场景的统一配色。科研分组按建筑等级展开，前置线展示工艺依赖，建筑入口承接跨组条件。

科技插画与团队头像使用内置 imagegen 生成，交付文件位于 `assets/technology/` 和 `assets/portraits/`。网页使用压缩后的 JPEG 图片；完整源图与含本机路径的生成记录仅保留在开发环境，不作为运行或发布依赖。

## 测试与构建

```sh
npm test
npm run build
npm run preview
```

构建产物位于 `dist/`，只包含 `index.html`、`src/` 中的 JS/CSS、`assets/` 中的图片/音频/字体和 `.nojekyll`。测试、开发脚本、本机配置、提示词清单和开发笔记不会进入部署产物。预览服务默认使用同样的 4173 端口；开发服务器仍在运行时，可使用 `npm run preview -- --port 4174`。

所有网页资源均采用相对路径，适用于 `https://用户名.github.io/仓库名/` 形式的 GitHub Pages 项目站点。

## 发布到 GitHub Pages

发布所需 workflow、构建脚本和忽略规则已经准备好，完整步骤见 [DEPLOY.md](DEPLOY.md)。当前目录尚未初始化 Git，也未创建远程仓库或执行上传。

你只需在首次推送命令中填入自己的 GitHub 仓库地址，并在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。源码和 workflow 无需填写用户名、仓库名或发布 Token；默认使用 `main` 分支。首次启用 Pages 后，可在 **Actions → Deploy GitHub Pages → Run workflow** 手动运行一次，日后推送 `main` 会自动测试、构建和发布。

Git 忽略 `dist/`、本机进度记录、截图和生成清单，保留游戏运行所需插画、头像与配乐。若更换发布分支，修改 `.github/workflows/pages.yml` 中的 `branches` 即可。

# 崇祯工业

一款回合制网页小游戏原型：在京师决战前，把工业试验变成持续供军的生产体系，把新军练成能够作战的部队。项目何时验收由玩家决定；提前交付能换来收益，继续准备则能提高成功率。

当前版本包含 51 项可研究科技、1 项自动胜利成果和 4 处关键营建，采用工场全景与浮窗操作。四次营建分别显现百工街巷、山麓炉场、水轮军器厂和演武营城，全部落成后组成一幅完整工业苑全景。研发按工业、军械与军制分类，已完成的工艺共同形成工业里程碑；最终能否守住北京，由对李自成、对清军的两线战力评分决定。

默认每回合一季、共 24 回合，从崇祯十一年夏开始，到崇祯十七年春结束。另有 40、64 回合选项，用于比较时间压力。战局新闻采用游戏化的历史背景，早期战果会影响威望与军情，最终截止回合保持固定。

## 本地启动

需要 Node.js 22 或更高版本，建议 Node.js 24。项目没有第三方运行或构建依赖，无须安装依赖。

```sh
npm run dev
```

在浏览器打开 <http://127.0.0.1:4173/>。开发服务器只监听本机。修改源文件后刷新浏览器即可看到变化。

更换端口：

```sh
npm run dev -- --port 4174
```

也可设置 `PORT` 环境变量。游戏使用 JavaScript modules，请通过本地 HTTP 服务打开，不要直接双击 `index.html`。

## 试玩

- 打开页面先进入标题界面，可选择「继续游戏」「新游戏」或「读取存档」。新游戏可选择 24、40、64 季；仅浏览标题页不会生成或覆盖存档。游戏右上角菜单按钮可返回标题。
- 「读取存档」支持此前导出的 JSON 卷宗（不超过 2 MB）。读取后先显示日期、季度和银两，确认后才替换当前进度；校验失败或取消读取不会改动原来的卷宗。
- 背景音乐为原创循环曲《甲申未至》，约 71 秒，无外部采样。首次点击后开始播放，标题页可以调整音量，标题页与游戏右上角都可开关音乐；偏好会保存在本机，页面隐藏时暂停。播放器独立于界面刷新，不因研究、换季或切换面板而重新播放。
- 从全景打开研发、营建、练军和目标浮窗；浮窗可收起，回到场景查看建设成果。
- 天工密录顶部显示工业里程碑，左侧团队栏贯通到底；右侧上方按工业、军械、军制三类展示科技卡片，下方三格详情依次显示团队与研究操作、科技作用与前置条件、技术背景知识。卡片区分已完成、待前置、本季已投入和可试验等状态；未解锁项目也能查看所缺条件。
- 先选左侧团队，再选科技，点击「研制」即可投入，无须下拉选择团队。所选团队的信息、研究进度与研制／验收按钮固定留在底部左栏；点击在研科技会自动选中负责团队，点击有任务的团队也会自动显示对应科技。没有研究任务时，两格科技详情显示空位。
- 技术背景栏直接展示技术概述、原理和历史沿革，不需要展开；玩法作用与前置条件在相邻的科技信息栏展示。
- 52 项科技成果各有独立配图；研究卡片以灰度图表示前置未满足，完成状态使用旧金边框与完成标记，选中状态另有边框强调，同时保留文字状态。工艺背景栏使用同一张淡化插画，保证背景文字可读。
- 点击里程碑会打开独立的条件浮窗。未完成研究的负责关系跨季保留，但不会自动投入经费或推进进度；浏览其他项目也不会改派任务，实际投入后才会更新负责关系。
- 工业里程碑由已完成工艺的能力等级自动汇总，不另占团队或收取验收费用。同一领域可以研究不同做法；达到里程碑后，仍可继续完成其他工艺，提升后续准备与军备能力。
- 开局有 5 支具名团队，各有数学、冶金、机械、洋务、军事与管理专长。研发时选择适合的团队，其专长影响本次投入推进的概率。研发、营建和操演会占用团队本季的工作机会，下季重新可用。
- 六类团队模板头像按最高能力自动适配；能力并列时按专长栏顺序固定选择。团队列表、研究详情、在署与候选卡片，以及营建、操演中的负责团队均展示对应头像。
- 可付费刷新候选团队、雇用或解雇团队，编制为 1 至 8 支；候选人被雇用后从候选名单移入现有团队。
- 先营建「基础工坊」，再推进勘察、量具、动力等基础研究；工业里程碑与建筑相互衔接，逐步打开后续研发。
- 建筑仅有 4 种，各营建一次：基础工坊（1.6 万两）、炼铁炉场（3 万两）、军器工场（4.8 万两）和演武场（2.8 万两）。科技以每次数千两的持续投入推进，建筑需要提前留银、攒够一次性营建费用。
- 不同工艺直接体现为科技树中的独立项目，例如土法块炼铁、水力木炭高炉与焦炭高炉。各项目有自己的研究工作量、前置和供军能力，不再额外切换「土法」或「正规工艺」。
- 研发投入与项目试验是两个决定。玩家可继续准备提高试验胜算，也可尽早验收争取威望；遇到可补救的问题时，能够使用剩余资金尝试一次紧急攻关。
- 验收前可选择是否邀请群臣观礼。观礼使成功的威望收益与最终失败的威望损失都翻倍，试验费用、成功率与技术进度损失不变；抢险沿用本次验收的观礼安排，只在最终结果确定时结算威望。
- 科技完成即生效，武器完成即计入军备，不追加换装或列装回合。不同兵器、弹药、产线与训练共同决定实际战力。
- 可选择冷兵器、胸甲骑兵、米尼步枪或后装步枪等军制重点。切换只调整作战方案和评分，已有科技、建筑与训练成果保留，研发目录不会隐藏其他路线。
- 对李自成、对清军的两线战力均达到 100 时，「新军守京」立即自动达成，当下获胜；不再要求统一攀完一套指定武器链。具体评分与短板以目标浮窗公开结果为准。
- 阶段新闻提供交付军需、派出新军或暂不响应等选择；局部战果影响威望与训练，最后期限始终不变。
- 开局内库可用银 3.5 万两。每季拨款为保底 6,000 两，加上每点朝廷威望对应的 200 两；科技首次完成增加威望，科技和建筑不另外产生经营收入。
- 朝廷威望降到负数时，立即触发「群臣进献红丸」结局，本局结束，不再拨款或推进季度；威望恰为零仍可继续。
- 最后一季仍可安排项目和训练，最后一项成果令两线战力达标也会立即获胜；结束最后一季仍未达标，本局失败。

浏览器会自动保存本地进度。存档属于当前浏览器与网址；更换端口、浏览器或部署到新网址后不会自动共享。清理站点数据会删除当地存档。原型不依赖账号、后端或云存储。

本轮采用 v4 存档，仅读取当前版本，不转换旧版原型数据。右上角可导出本局 JSON 文件留存；载入时会校验团队、项目、回合、待处理决策和胜负状态。工业里程碑与战力评分由现有成果重新计算，不作为独立数值写入存档。

## 史实与游戏依赖

技术背景文字仅介绍技术原理与历史沿革，并提供可查阅的来源。科技作用、依赖关系和准备进度另由界面展示；科技树中的前置关系是玩法设计，不等同于真实历史的发展次序。

界面采用暗朱漆、旧金、乌木与暖灰纸的配色，取材于明代宫廷语境下的红墙黄瓦和剔红器物，参考[故宫《硃黄显尊贵》](https://www.dpm.org.cn/historical/talk/204840.html)与[国家博物馆藏明代剔红盒](https://www.chnmuseum.cn/zp/zpml/csp/201812/t20181218_25430.shtml)。这是一套服务于游戏气氛的宫廷主题，不代表明代所有场景的统一配色。八个里程碑使用尺规、铁锭、齿轮、量具、火药桶、铁砧、营制和线膛枪等图标，避免把多种达成路线固定为某一种技术图景。

科技插画与团队头像使用内置 imagegen 生成，交付文件位于 `assets/technology/` 和 `assets/portraits/`。网页使用压缩后的 JPEG 图片；完整源图与含本机路径的生成记录仅保留在开发环境，不作为运行或发布依赖。

## 测试与构建

```sh
npm test
npm run build
npm run preview
```

构建产物位于 `dist/`，只包含 `index.html`、`src/` 中的 JS/CSS、`assets/` 中的图片/音频/字体和 `.nojekyll`。测试、开发脚本、本机配置、提示词清单和开发笔记不会进入部署产物。预览服务默认使用同样的 4173 端口；开发服务器仍在运行时，可使用 `npm run preview -- --port 4174`。

所有网页资源均采用相对路径，适用于 `https://用户名.github.io/仓库名/` 形式的 GitHub Pages 项目站点。

## 发布到 GitHub Pages

发布所需 workflow、构建脚本和忽略规则已经准备好，完整步骤见 [DEPLOY.md](DEPLOY.md)。当前目录尚未初始化 Git，也未创建远程仓库或执行上传。

你只需在首次推送命令中填入自己的 GitHub 仓库地址，并在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**。源码和 workflow 无需填写用户名、仓库名或发布 Token；默认使用 `main` 分支。首次启用 Pages 后，可在 **Actions → Deploy GitHub Pages → Run workflow** 手动运行一次，日后推送 `main` 会自动测试、构建和发布。

Git 忽略 `dist/`、本机进度记录、截图和生成清单，保留游戏运行所需插画、头像与配乐。若更换发布分支，修改 `.github/workflows/pages.yml` 中的 `branches` 即可。

## 源码结构

```text
index.html                    页面入口
src/technology.js             科技、建筑、里程碑与作战方略目录
src/game.js                   游戏规则和回合结算
src/storage.js                v4 存档格式校验与解析
src/save-slot.js              标题页存档读取、文件校验和本地保存
src/title-screen.js           标题菜单与存档摘要
src/music.js                  循环配乐、音量与播放状态
src/                          界面与样式
assets/                       静态美术资源
tests/                        游戏规则测试
scripts/serve.mjs              本地静态服务
scripts/build.mjs              静态文件构建
scripts/compose-score.py       原创配乐生成脚本（仅改编音乐时需要）
.github/workflows/pages.yml    GitHub Pages 自动部署
```

本原型优先验证决策节奏、项目继承与军队成长。项目价格、成功率、训练收益和事件奖励仍需实际试玩调校。
